# progress-abstract 使用说明

个人推进记忆目录。本 README 是记忆维护规则的**唯一权威来源**，`index.md` 与 `AGENTS.md` 只保留要点并引用本文件。
除本 README 外，其余内容一律不纳入 git 追踪、不随仓库共享；协作方以 `project-schedule.md` 中的模块进度为准。

## 维护规则

1. 新增修改内容：在 `仍然需要留意的推进/` 下新建记录 md（命名 `YYYY-MM-DD-主题.md`），并同步更新 `index.md`。
2. 记录已过时或对当前开发无影响：移入 `已过时的推进/`，并同步更新 `index.md`。
3. 新建或调整记录/索引前，先判断是否需要，并用文字询问用户。
4. 判断模块/子任务已完成时，向用户提出载入 schedule 进度（更新 `project-schedule.md`），由用户决定。

## 目录结构

```text
progress-abstract/
├── README.md               # 本文件：规则与结构说明（随仓库追踪）
├── index.md                # 近期修改索引：只维护两个列表（个人，不追踪）
├── 仍然需要留意的推进/      # 仍影响当前开发的修改记录（个人，不追踪）
│   └── YYYY-MM-DD-主题.md
└── 已过时的推进/            # 已过时/对当前开发无影响的记录（个人，不追踪）
    └── YYYY-MM-DD-主题.md
```

## index.md 的结构

```markdown
# 近期修改索引

> 维护规则见 README.md；本文件只维护列表。

## 仍然需要留意的推进

- 记录列表（链接到对应的 md）

## 已过时的推进

- 记录列表（链接到对应的 md）
```

## 修改记录 md 的结构

```markdown
# YYYY-MM-DD 修改主题

- 涉及模块：
- 修改内容：
- 对当前开发的影响：
- 关联 schedule 子任务：
- 状态：仍然需要留意 / 已过时
```
